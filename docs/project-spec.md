# Спецификация проекта «Temkastar»

## 1. Общая информация

**Название:** «Temkastar»
**Тип:** игровая web-платформа для открытия кейсов с Telegram-подарками
**Текущий этап:** задание №1 — проектирование предметной области и развёртывание React-каркаса
**Технологии текущего этапа:** React, JavaScript, Vite, CSS.
**Backend:** будет написан отдельно на следующем этапе курса.

Цель проекта — помочь пользователю открывать кейсы с Telegram-подарками, следить за своим инвентарём, улучшать предметы и выводить их в Telegram.

## 2. Пользователь и проблема

### Основной пользователь

Игрок, который коллекционирует Telegram-подарки и хочет получать новые через механику кейсов, а также улучшать и выводить предметы.

### Проблема пользователя

Игроки, которым нужны Telegram-подарки по низким ценам, вынуждены пользоваться разрозненными инструментами: одни боты продают подарки, другие — только открывают кейсы, третьи — позволяют обмениваться. Единой площадки с кейсами, апгрейдом и выводом одновременно нет, или цены на таких площадках очень высоки. Это приводит к:

- потере времени на переходы между сервисами;
- невозможности быстро превратить подарок в деньги или улучшить его;
- отсутствию единой истории открытий и статистики;
- непрозрачным шансам выпадения предметов.

### Пользовательская ценность

Пользователь открывает приложение и за несколько секунд получает ответ на три вопроса:

1. Какие кейсы доступны и что в них может выпасть?
2. Что уже есть в моём инвентаре и что с этим можно сделать?
3. Как открыть кейс, улучшить предмет или вывести подарок?

## 3. Цель первой версии

В первой версии нужно создать понятный интерфейс обзора кейсов и подготовить основу для дальнейшей разработки.

На первом этапе приложение должно:

- запускаться локально как React-приложение;
- содержать модель кейса и связанных сущностей;
- отображать демонстрационный список кейсов;
- показывать цену, редкость и количество предметов внутри;
- вычислять статус кейса по цене и активности;
- объяснять, какие страницы и пользовательские сценарии будут реализованы дальше.

Полноценные формы, оплата и вывод подарков будут добавляться постепенно, поэтому сейчас используются локальные mock-данные.

## 4. Основная сущность

Главная сущность приложения — **Case** («кейс»). Один кейс описывает набор предметов с ценой открытия и шансами выпадения.

### Поля сущности

| Поле | Тип | Обязательность | Пример | Назначение и правила |
|---|---|---:|---|---|
| `id` | `number` | да | `1` | Уникальный идентификатор кейса. |
| `name` | `string` | да | `Стартовый кейс` | Короткое название. Не может быть пустым. |
| `description` | `string` | нет | `Для новичков` | Дополнительное описание. |
| `price` | `number` | да | `299` | Стоимость открытия в рублях. Не может быть отрицательной. |
| `items` | `array` | да | — | Список предметов внутри кейса. |
| `imageUrl` | `string` | нет | `/cases/start_case.png` | Обложка кейса. |
| `totalOpens` | `number` | нет | `1542` | Сколько раз кейс открывали. |
| `dropChance` | `number` | нет | `0.85` | Средняя вероятность выпадения предмета. |
| `isActive` | `boolean` | да | `true` | Доступен ли кейс для открытия. |

Таким образом, сущность содержит строковые поля, число, массив объектов, перечисление и логическое поле. Это позволяет использовать разные типы данных уже на первом учебном этапе.

## 5. Страницы и маршруты

В приложении должны быть отдельные страницы с отдельными URL. Переключение экранов вкладками внутри одного компонента не считается выполнением этого требования.

Ниже описан минимальный набор экранов. Реализация маршрутизации и самих страниц выполняется в следующих заданиях.

### Страница 1. Главная

**URL:** `/`

**Назначение:** дать пользователю краткий обзор кейсов и быстрых действий сразу после открытия приложения.

**Что отображается:**

- количество доступных кейсов;
- стоимость открытия;
- короткий список всех кейсов;
- быстрые ссылки на профиль, апгрейд и рейтинг.

**Действия пользователя:**

- перейти к карточке кейса;
- перейти в профиль;
- перейти к апгрейду;
- перейти к рейтингу;
- перейти к авторизации или регистрации.

### Страница 2. Карточка кейса

**URL:** `/:caseId`

**Назначение:** показать содержимое кейса и дать возможность его открыть.

**Что отображается:**

- название, описание и обложка;
- цена открытия;
- список предметов с редкостями и шансами;
- средняя стоимость предмета;
- количество открытий;
- кнопка «Открыть».

**Действия пользователя:**

- открыть кейс;
- посмотреть шансы на каждый предмет;
- вернуться к списку;
- перейти к похожим кейсам.

### Страница 3. Апгрейд

**URL:** `/upgrade`

**Назначение:** позволить пользователю обменять предмет на более дорогой с шансом успеха.

**Что отображается:**

- выбранный предмет и его стоимость;
- список доступных предметов для апгрейда;
- расчёт шанса успеха;
- потенциальная выгода.

**Действия пользователя:**

- выбрать предмет из инвентаря;
- выбрать целевой предмет;
- увидеть шанс успеха;
- запустить апгрейд;
- увидеть результат.

### Страница 4. Профиль

**URL:** `/profile`

**Назначение:** показать статистику, историю и инвентарь пользователя.

**Что отображается:**

- баланс;
- количество открытых кейсов;
- суммарная стоимость инвентаря;
- список подарков;
- редкость и стоимость каждого;
- дата выпадения;
- история открытий, апгрейдов и выводов.

**Действия пользователя:**

- сортировать инвентарь по цене, редкости и дате;
- фильтровать по редкости и статусу;
- выбрать предмет для апгрейда;
- выбрать предмет для вывода;
- посмотреть историю.

### Страница 5. Авторизация

**URL:** `/authorization`

**Назначение:** дать пользователю войти в аккаунт.

**Что отображается:**

- поле логина;
- поле пароля;
- кнопка «Войти»;
- ссылка на регистрацию.

**Действия пользователя:**

- ввести данные;
- увидеть ошибку при неверных данных;
- войти в аккаунт;
- перейти к регистрации.

### Страница 6. Регистрация

**URL:** `/registration`

**Назначение:** дать пользователю создать аккаунт.

**Что отображается:**

- поля логина, пароля и подтверждения;
- кнопка «Зарегистрироваться»;
- ссылка на авторизацию.

**Действия пользователя:**

- ввести данные;
- увидеть ошибки валидации;
- создать аккаунт;
- перейти к авторизации.

### Страница 7. Рейтинг

**URL:** `/rating`

**Назначение:** показать таблицу лидеров и место пользователя.

**Что отображается:**

- таблица игроков;
- количество открытий у каждого;
- суммарная стоимость выигрышей;
- место текущего пользователя.

**Действия пользователя:**

- посмотреть своё место;
- понять, сколько нужно открытий до следующей позиции;
- перейти в профиль другого игрока.

### Страница 8. Профиль (расширенный)

**URL:** `/profile`

**Назначение:** дополнительный блок со статистикой и историей.

**Что отображается:**

- баланс;
- статистика по редкостям;
- история операций;
- настройки аккаунта.

**Действия пользователя:**

- пополнить баланс;
- посмотреть историю;
- изменить настройки;
- выйти из аккаунта.

В будущих заданиях также появятся маршруты `/:caseId/open` для анимации открытия и `/battles/:battleId` для просмотра конкретного баттла.

## 6. Пользовательские сценарии

Каждый сценарий описывает путь пользователя от начального действия до ожидаемого результата.

### Сценарий 1. Открытие кейса

1. Пользователь открывает `/:caseId`.
2. Нажимает «Открыть».
3. Подтверждает списание с баланса.
4. Видит анимацию прокрутки.
5. Получает случайный предмет, который попадает в инвентарь.

**Ожидаемый результат:** предмет добавлен в инвентарь, баланс уменьшен на стоимость кейса.

### Сценарий 2. Просмотр профиля

1. Пользователь открывает `/profile`.
2. Видит список своих подарков.
3. Сортирует их по цене и редкости.
4. Открывает карточку одного предмета.
5. Анализирует статистику своего аккаунта.

**Ожидаемый результат:** пользователь видит все свои предметы и может выбрать нужный для дальнейших действий.

### Сценарий 3. Апгрейд предмета

1. Пользователь открывает `/upgrade`.
2. Выбирает предмет из инвентаря.
3. Выбирает целевой предмет дороже.
4. Видит шанс успеха.
5. Запускает апгрейд.
6. При успехе получает новый предмет, при неудаче — теряет старый.

**Ожидаемый результат:** инвентарь обновляется в соответствии с результатом апгрейда.

### Сценарий 4. Вывод подарка

1. Пользователь открывает `/profile`.
2. Выбирает предмет из инвентаря.
3. Указывает получателя.
4. Подтверждает вывод.
5. Видит статус вывода.

**Ожидаемый результат:** предмет отправлен в Telegram-аккаунт, из инвентаря удалён.

### Сценарий 5. Баттл с другим игроком

1. Пользователь открывает `/rating`.
2. Смотрит своё положение в таблице лидеров.
3. Понимает, сколько ему нужно совершить открытий, чтобы стать лидером.
4. Переходит в профиль другого игрока.
5. Возвращается к своим кейсам.

**Ожидаемый результат:** пользователь понимает своё место в рейтинге и мотивирован открывать больше кейсов.

## 7. Действия над сущностью Case

С кейсом и связанными сущностями должны поддерживаться следующие операции:

- открыть подробности кейса;
- открыть кейс и получить предмет;
- добавить предмет в инвентарь;
- выставить предмет на апгрейд;
- вывести предмет с платформы;
- продать предмет на платформе;
- найти, отфильтровать и отсортировать кейсы в инвентаре;
- использовать данные о кейсах для расчёта вероятностей.

## 8. Технические требования

### Обязательные требования текущего задания

- проект создан через Vite;
- используется React и JavaScript;
- приложение запускается командой `npm run dev`;
- production-сборка проходит командой `npm run build`;
- создан Git-репозиторий и первый коммит;
- в корне есть README с описанием и командами запуска;
- в `docs/project-spec.md` есть описание темы, сущности, страниц и сценариев;
- приложение не является только статическим лендингом или одной формой;
- будущие экраны спроектированы как отдельные маршруты, а не вкладки внутри одной страницы.

### Ограничения реализации первого этапа

- состояние React и Redux Toolkit пока не подключаются;
- backend не требуется;
- авторизация,  платежи и вывод подарков не подключаются.

## 9. Что не входит в первую версию

Следующие функции оставлены для следующих заданий или отдельного блока курса:

- подключение backend и базы данных;
- Redux Toolkit и глобальное состояние;
- полноценная маршрутизация;
- сохранение в localStorage;
- авторизация через Telegram;
- реальные платежи и депозит;
- интеграция с Telegram API для вывода подарков;
- баттлы в реальном времени;
- push-уведомления о выпадении редких предметов;
- синхронизация между устройствами;
- система рефералов и бонусов;
- история транзакций и статистика по пользователям.
